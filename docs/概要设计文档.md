## 1. 系统架构设计

### 1.1 系统架构概述

本系统采用经典的**前后端分离架构**（B/S模式），整体分为表现层（前端）、业务逻辑层（后端）、数据层（数据库）三层。

```
┌──────────────────────────────────────────────────────────┐
│                      客户端浏览器                          │
│         (Vue.js + Element UI + ECharts)                   │
└────────────────────────┬─────────────────────────────────┘
                         │ HTTP/HTTPS (RESTful API)
                         │ JSON
┌────────────────────────▼─────────────────────────────────┐
│                    应用服务器                              │
│         (Spring Boot + MyBatis Plus + JWT)                │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────────┐   │
│  │ Controller  │→ │   Service   │→ │ Mapper (MyBatis)│   │
│  │   层        │  │    层       │  │      层         │   │
│  └─────────────┘  └─────────────┘  └─────────────────┘   │
└────────────────────────┬─────────────────────────────────┘
                         │ JDBC
┌────────────────────────▼─────────────────────────────────┐
│                     MySQL 数据库                          │
│              (gym_db, UTF-8 编码)                        │
└──────────────────────────────────────────────────────────┘
                         │
                  ┌──────▼──────┐
                  │  文件存储   │
                  │ uploads/    │
                  │  本地磁盘   │
                  └─────────────┘
```

## 2. 数据库设计

### 2.1 数据库命名规范

- 数据库名称：`gym_db`
- 字符集：`utf8mb4`（支持emoji和特殊字符）
- 排序规则：`utf8mb4_general_ci`
- 表名命名：snake_case（全部小写，以下划线分隔），前缀按模块区分

| 前缀 | 所属模块 |
|-----|---------|
| `user_` | 用户认证模块 |
| `member_` | 会员管理模块 |
| `coach_` | 教练管理模块 |
| `course_` | 课程管理模块 |
| `equipment_` | 器材管理模块 |
| `points_` | 积分商城模块 |

### 2.2 核心表结构

#### 2.2.1 用户认证模块

**表: user_info（用户信息表）**

| 字段名 | 类型 | 约束 | 说明 |
|-------|------|------|------|
| user_id | BIGINT | PK, AUTO_INCREMENT | 用户ID |
| username | VARCHAR(50) | UNIQUE, NOT NULL | 用户名 |
| password | VARCHAR(255) | NOT NULL | 密码（BCrypt加密） |
| user_type | TINYINT | NOT NULL | 用户类型：1=管理员 2=教练 3=会员 |
| member_id | BIGINT | FK, NULL | 会员ID（user_type=3时有效） |
| coach_id | BIGINT | FK, NULL | 教练ID（user_type=2时有效） |
| status | TINYINT | DEFAULT 1 | 状态：0=禁用 1=启用 |
| deleted | TINYINT | DEFAULT 0 | 逻辑删除：0=未删 1=已删 |
| create_time | DATETIME | DEFAULT NOW() | 创建时间 |
| update_time | DATETIME | ON UPDATE NOW() | 更新时间 |

**索引设计:**
- `idx_username_type` (username, user_type) — 登录查询
- `idx_member_id` (member_id) — 会员关联
- `idx_coach_id` (coach_id) — 教练关联

## 3. 接口设计

### 3.1 接口规范

#### 通用规范

- **通信协议**: HTTP/HTTPS
- **数据格式**: JSON
- **字符编码**: UTF-8
- **认证方式**: Bearer Token（JWT）
- **请求头**: `Authorization: Bearer <token>`
- **日期格式**: `yyyy-MM-dd HH:mm:ss`
- **分页参数**: `pageNum`（页码，从1开始）、`pageSize`（每页条数，默认10）

#### 统一响应格式

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

| HTTP状态码 | code | 说明 |
|-----------|------|------|
| 200 | 200 | 成功 |
| 400 | 400 | 请求参数错误 |
| 401 | 401 | 未认证（Token无效或过期） |
| 403 | 403 | 无权限访问 |
| 404 | 404 | 资源不存在 |
| 500 | 500 | 服务器内部错误 |

## 4. 安全设计

### 4.1 身份认证

- 所有API接口（除登录接口外）均需携带有效JWT Token
- JWT Token 有效期24小时，过期后前端跳转至登录页
- Token 包含用户ID、用户名、用户类型等关键信息
- Token 存储于 localStorage，登录时通过 Authorization Header 传递

### 4.2 密码安全

- 用户密码使用 BCrypt 算法加密存储，强度因子10
- 前端不存储明文密码
- 密码修改需校验原密码

### 4.3 权限控制

- 基于 Spring Security 的 URL 级权限控制
- 基于前端 Vue Router 的菜单级权限过滤
- 后端接口按 userType 区分访问权限
- 教练接口仅限 userType=2 的用户访问
- 会员接口仅限 userType=3 的用户访问
- 管理员接口仅限 userType=1 的用户访问

### 4.4 数据安全

- 敏感操作（删除、扣费）记录操作日志
- 财务数据（消费记录、工资单）不可物理删除
- 文件上传限制格式（jpg/png/gif/webp）和大小（5MB）
- SQL 注入防护：使用 MyBatis 参数化查询
- XSS 防护：后端统一处理特殊字符转义

## 6. 系统扩展性设计

### 6.1 横向扩展

- 后端无状态设计，支持多实例水平扩展
- Session 通过 JWT 管理，无需 Redis 共享
- 数据库读写分离可按需引入

### 6.2 功能扩展

- 采用 RESTful API，后续可扩展移动端（iOS/Android）
- 模块化设计，新增功能只需增加 Controller/Service/Mapper
- Vue 组件化，前端扩展灵活

### 6.3 数据扩展

- MyBatis Plus 支持动态SQL，便于复杂查询扩展
- JSON 字段可用于存储灵活扩展字段
- 积分商品支持关联外部系统
