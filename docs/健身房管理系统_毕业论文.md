# 健身房管理系统设计与实现

---

## 摘要

本论文针对健身房日常运营管理信息化需求，设计并实现了一套功能完整的健身房管理系统（*Gym Management System*）。系统基于 Spring Boot 框架构建后端 RESTful API，采用 Vue.js 前端框架实现多角色用户界面，运用 MyBatis-Plus 作为 ORM 工具，MySQL 8.0 作为数据持久化引擎。系统覆盖会员管理、教练管理、课程预约与排班、器材管理、体测健康档案、积分商城、教练绩效与工资管理、会所签到等核心业务模块，支持管理员、教练、会员三种角色，各角色拥有独立的功能视图与数据权限。系统采用 JWT（JSON Web Token）实现身份认证与授权，采用 Spring Security 实现基于角色的访问控制（RBAC）。目前系统已完成开发并可正常运行，为健身房日常运营提供了高效的信息化管理手段。

**关键词**：健身房管理系统；Spring Boot；Vue.js；MyBatis-Plus；JWT 认证

## 第一章 绪论

### 1.1 课题意义和目标

随着全民健身意识的不断增强，健身行业呈现快速发展的态势。然而，传统健身房在会员管理、课程预约、教练排班、器材维护等方面的信息化程度普遍较低，大量日常运营工作仍依赖人工处理，效率低下且易出错。主要体现在以下几个方面：

（1）**会员管理效率低**。会员档案、签到记录、体测数据、积分变动等数据分散在纸质或电子表格中，查询统计困难，无法为会员提供个性化的健身指导。

（2）**课程管理缺乏联动**。教练排班与会员可预约课程之间缺乏自动同步机制，课程信息更新滞后，影响会员体验和场馆利用率。

（3）**教练绩效不透明**。教练的课时数、课时费、绩效奖金等收入信息由管理员单独维护，教练无法实时查询，降低了教练的工作积极性。

（4）**会员健康档案缺失**。会员的体测数据、训练计划、训练反馈等信息没有系统化的记录和管理，教练难以制定科学的个性化训练方案。

（5）**积分激励机制不完善**。缺乏系统化的积分获取与消耗规则，无法通过积分商城等激励机制提升会员活跃度和忠诚度。

针对上述问题，本课题设计并实现了一套功能完整的健身房管理系统，目标如下：

- 实现会员、教练、课程、器材等核心资源的数字化管理，减少人工操作；
- 构建多角色协同平台，支持管理员、教练、会员三类用户；
- 实现课程预约、教练排班、积分商城等业务闭环；
- 提供教练绩效工资透明化、会员健康档案管理、课程评价等功能；
- 保证系统的安全性、稳定性和易用性。

### 1.2 国内外研究现状

在健身行业信息化方面，国内外已有不少成熟的 SaaS 平台，如 Mindbody、Fitbits、Keep 等。这些平台主要面向大型连锁健身房，提供会员管理、课程预约、支付结算等标准化功能。然而，针对中小型单体健身房，这些平台存在以下不足：功能过于复杂，学习成本高；价格高昂，不适合小规模场馆；定制化程度低，难以适应特定业务需求。

在技术选型方面，Spring Boot + Vue.js 的全栈组合因其前后端分离架构清晰、开发效率高、社区生态成熟等优势，已成为国内中小型管理系统开发的主流方案。MyBatis-Plus 作为 MyBatis 的增强工具，提供了强大的 CRUD 封装和分页插件，大幅降低了持久层开发工作量。JWT 认证因其无状态、可扩展的特性，在分布式系统中的身份认证场景得到广泛应用。

本课题在参考上述技术方案的基础上，结合健身房管理实际需求，设计了一套轻量级、高可用、可扩展的管理系统。

### 1.3 主要工作

本课题的主要工作包括以下几个方面：

（1）**需求分析与系统设计**。通过对健身房日常运营业务的深入调研，明确系统功能需求，进行可行性分析，设计系统的总体架构和数据库结构。

（2）**后端系统开发**。基于 Spring Boot 框架，开发 RESTful API，实现会员管理、教练管理、课程预约与排班、器材管理、体测档案、积分商城、绩效工资管理等核心功能模块。

（3）**前端系统开发**。基于 Vue.js 2.x 和 Element UI 组件库，为管理员、教练、会员三种角色分别开发独立的功能界面。

（4）**安全机制设计**。实现基于 JWT 的身份认证和基于 Spring Security 的角色访问控制，保证系统数据安全。

（5）**业务闭环设计**。实现教练排班与会员可预约课程自动联动、调班请假自动通知会员、教练评价回复等业务闭环。

（6）**系统测试**。编写测试用例，对核心功能进行功能测试和集成测试，验证系统的正确性和稳定性。

## 第二章 系统分析

### 2.1 可行性分析

#### 2.1.1 技术可行性

本系统采用的技术栈均为业界成熟方案，具体分析如下：

**后端技术**：Spring Boot 是目前 Java 生态中最成熟的微服务快速开发框架，提供了自动配置、内嵌服务器、starter 依赖等便利特性。Spring Security 提供了完整的认证授权框架，结合 JWT 可实现无状态的身份认证。MyBatis-Plus 在 MyBatis 基础上提供了强大的 CRUD 增强和分页插件，开发效率高。MySQL 8.0 作为开源关系型数据库，支持事务、视图、存储过程等企业级特性，能够满足本系统的数据持久化需求。

**前端技术**：Vue.js 2.x 是国内使用最广泛的前端框架之一，生态成熟，文档完善。Element UI 提供了一套完整的企业级 UI 组件库，显著降低了界面开发工作量。Vuex 提供了可靠的状态管理机制，Vue Router 实现了前端路由的模块化管理。

**可行性结论**：上述技术均有大量工程实践，技术可行性明确。

#### 2.1.2 经济可行性

本系统采用的开发工具和运行环境均为开源或免费方案：IntelliJ IDEA 社区版、Visual Studio Code、MySQL Community Edition、Node.js 等均免费可用。服务器端可部署在普通 PC 或云服务器上，硬件要求低。综合来看，系统开发成本和运行成本均在可接受范围内。

#### 2.1.3 操作可行性

系统采用 B/S 架构，用户通过浏览器即可访问，无需安装专门的客户端软件。界面设计遵循用户习惯，操作流程简洁明了，对计算机操作水平一般的健身房工作人员和会员均易于上手。

### 2.2 需求分析

#### 2.2.1 系统用户角色

本系统面向三类用户角色，每类角色拥有独立的功能视图：

**管理员**（UserType = 1）：健身房管理人员。负责系统全局数据管理，包括会员管理、教练管理、课程管理、器材管理、排班管理、绩效工资管理、证书管理等，是系统的核心使用者。

**教练**（UserType = 2）：健身房的教练人员。负责管理个人课程排班、查看所负责会员的健康档案和体测数据、布置课后作业、与会员沟通、查看个人绩效评分和工资收入、回复会员评价等。

**会员**（UserType = 3）：健身房注册会员。通过系统完成注册登录、预约课程、每日签到、查看体测记录、管理个人积分、兑换积分商城商品、联系教练、接收系统通知等。

#### 2.2.2 功能性需求

通过对健身房实际业务的调研分析，本系统的功能性需求如下：

**会员端核心功能：**

（1）**会员注册与登录**。会员通过注册页面创建账号（录入用户名、密码、选择角色为会员），系统自动生成会员档案（默认健身水平为初级、积分为0）。会员使用用户名密码登录，支持记住登录状态。

（2）**课程预约**。会员可浏览可预约课程列表（由教练排班自动生成，未来7天内所有待上课排班），选择课程并完成预约。预约成功后记录积分明细（预约课程+5积分）。

（3）**每日签到**。会员可每日签到获取积分（每日签到+10积分），系统自动计算连续签到天数。

（4）**体测档案管理**。会员可录入个人体测数据（身高、体重、BMI、体脂率、肌肉量等），查看体测历史记录，教练也可代为录入。

（5）**积分商城**。会员可使用积分兑换商品（实物）或课程（虚拟），兑换记录实时更新会员积分余额。

（6）**积分任务中心**。会员可查看当前积分、各类积分任务的完成状态（签到、完成课程、评价课程等）。

（7）**课后作业**。教练布置的课后作业在会员端展示，会员可标记完成。

（8）**课程评价**。会员完成课程后，可对课程进行评分和文字评价（评价课程+10积分），教练可回复评价。

（9）**消息通知**。会员接收系统推送的课程预约确认、教练回复、调班通知等消息。

**教练端核心功能：**

（1）**教练首页仪表盘**。展示今日课程数、本月课时数、学员评分、出勤率、待办事项等统计数据。

（2）**课程排班管理**。教练可管理个人排班（日期、时间、课程、地点），排班数据自动出现在会员可预约课程列表中，无需人工同步。

（3）**调班/请假申请**。教练提交调班申请（选择原排班日期、目标日期、调班原因），管理员审批后自动更新相关排班时间，并通过系统消息通知已预约的会员。

（4）**所负责会员管理**。教练可查看所负责的所有会员列表，显示每个会员的累计课程数、已完成课程数、剩余课时、最近上课日期。点击会员可查看详细信息（基本信息、课程记录、体测记录、评价记录）。

（5）**体测数据录入**。教练可为所负责的会员录入体测数据。

（6）**课后作业布置**。教练可向会员布置课后作业，设置目标完成日期。

（7）**绩效与工资透明化**。教练可实时查看个人绩效评分（出勤评分、教学评分、服务评分、销售评分、学员反馈评分）和工资收入（基本工资、课时费、绩效奖金），支持按月筛选和收入趋势图展示。

（8）**课程评价查看与回复**。教练可查看会员对自己的课程评价内容，并可回复。回复后系统自动向会员推送通知。

**管理员端核心功能：**

（1）**会员管理**。管理所有会员档案，可新增、编辑、删除会员，可调整会员积分，可将会员分配给指定教练。

（2）**教练管理**。管理所有教练档案，审核教练资质证书，管理教练特长标签。

（3）**课程管理**。管理课程目录（课程名称、教练、类型、时长、价格、容量、上课地点等），设置课程分类。

（4）**器材管理**。管理器材库存（名称、类型、品牌、型号、采购日期、维护日期），上传器材图片。

（5）**会员卡管理**。管理会员的健身卡（卡种类型、总次数/总金额、已用次数/余额、到期日期），支持续卡、挂失、补办等操作。

（6）**消费记录管理**。记录会员各项消费（购卡、购课、私教等），可按时间、类型、会员等条件查询统计。

（7）**签到记录管理**。查看所有会员的签到记录和连续签到统计。

（8）**排班管理**。统一管理所有教练的课程排班，审核调班申请。

（9）**绩效管理**。为教练录入月度绩效评分记录。

（10）**工资管理**。为教练录入月度工资记录（基本工资、课时费、绩效奖金等）。

（11）**积分商品管理**。管理积分商城的商品目录（商品名称、所需积分、库存、图片），审核积分兑换记录。

（12）**统计面板**。展示系统全局运营数据（会员总数、教练总数、课程数、器材状态分布等）。

#### 2.2.3 非功能性需求

（1）**性能需求**：系统应能支持至少 100 名并发用户，页面响应时间不超过 2 秒。

（2）**安全性需求**：所有敏感操作（密码修改、积分调整、删除操作等）需经过身份验证；不同角色只能访问对应权限范围内的数据。

（3）**可靠性需求**：系统应保证数据的逻辑完整性，所有删除操作采用逻辑删除而非物理删除，防止数据误删。

（4）**可维护性需求**：前后端采用分离架构，便于独立维护和扩展；数据库设计遵循规范化原则，消除数据冗余。

### 2.3 方案比选

#### 2.3.1 整体架构方案

**方案一：单体架构**。将所有功能模块打包为一个部署单元，部署在单台服务器上。

**方案二：前后端分离架构**。后端以 RESTful API 形式提供数据接口，前端独立部署，通过 HTTP 协议与后端通信。

本系统选择**方案二**，理由如下：前后端分离使开发团队可并行工作，提高开发效率；前端可单独部署到 CDN 或静态服务器，后端可单独扩展；接口标准化使系统具备良好的可扩展性，后续可支持小程序、APP 等多端接入。

#### 2.3.2 后端框架选型

**方案一：Spring MVC + MyBatis**。传统 Java Web 开发方案，需要手动配置大量 XML，CRUD 代码量大。

**方案二：Spring Boot + MyBatis-Plus**。Spring Boot 提供自动配置能力，MyBatis-Plus 提供增强的 CRUD 操作和分页插件，开发效率显著高于方案一。

本系统选择**方案二**，理由如下：Spring Boot 的 starter 依赖机制减少了大量配置工作；MyBatis-Plus 的 EntityWrapper 和 LambdaQueryWrapper 使查询条件构建更加类型安全；分页插件无需手动处理分页逻辑。

#### 2.3.3 前端框架选型

**方案一：React + Ant Design**。React 生态成熟，但学习曲线较陡，JSX 语法对习惯模板语法的开发者不够友好。

**方案二：Vue.js 2.x + Element UI**。Vue 的响应式数据绑定和组件化开发模式使开发效率高，Element UI 提供了一套完整的企业级 UI 组件库，与 Vue 深度集成。

本系统选择**方案二**，理由如下：Vue 的单文件组件（.vue）将模板、脚本、样式组织在一起，开发体验好；Element UI 的组件覆盖了管理系统中的大部分 UI 场景；Vuex 提供了完善的状态管理机制，适合多角色复杂交互场景。

#### 2.3.4 数据库选型

**方案一：MongoDB**。NoSQL 文档数据库，适合数据结构多变的场景，但不适合强关系型数据建模。

**方案二：MySQL 8.0**。关系型数据库，SQL 标准支持完善，事务处理能力强，运维工具成熟。

本系统选择**方案二**，理由如下：健身房管理涉及大量实体间的关联关系（会员-课程-教练-器材），适合用关系型数据库建模；MySQL 性能稳定，运维成本低；MyBatis-Plus 对 MySQL 的支持最为完善。

## 第三章 系统的设计

### 3.1 软件体系结构

本系统采用**前后端分离的多层架构**。

**后端**按职责分为以下层次：

- **Controller 层**（`com.gym.controller`）：接收 HTTP 请求，参数校验，调用 Service 层处理业务，返回 ApiResponse 统一响应格式。
- **Service 层**（`com.gym.service.impl`）：实现核心业务逻辑，处理事务管理，调用 Mapper 层进行数据持久化。
- **Mapper 层**（`com.gym.mapper`）：继承 MyBatis-Plus 的 BaseMapper，提供 CRUD 数据访问能力，由 MyBatis-Plus 通过 `@MapperScan` 自动注册。
- **Entity 层**（`com.gym.entity`）：与数据库表一一对应的 Java 实体类，使用 Lombok 的 `@Data` 注解自动生成 getter/setter，通过 `@TableName`、`@TableField`、`@TableId` 等注解与数据库表字段映射。
- **Config 层**（`com.gym.config`）：系统级配置类，包括 Spring Security 安全配置（SecurityConfig）、JWT 工具类（JwtUtil）、Web 配置（WebMvcConfig）、MyBatis-Plus 全局配置（MybatisPlusConfig）。
- **Filter 层**（`com.gym.filter`）：JwtAuthenticationFilter 过滤器，拦截所有 HTTP 请求，解析 JWT Token，将用户信息写入 SecurityContext。
- **Exception 层**（`com.gym.exception`）：GlobalExceptionHandler 统一异常处理器，对 RuntimeException 和一般 Exception 进行统一格式的响应包装。

**前端**按职责分为以下层次：

- **View 层**（`src/views/`）：Vue 单文件组件，包含页面模板（template）、业务逻辑（script）和样式（style scoped）。
- **API 层**（`src/api/`）：封装 Axios HTTP 请求，统一管理后端接口地址和请求参数。
- **Store 层**（`src/store/`）：Vuex 状态管理，user 模块管理用户登录状态和基本信息。
- **Router 层**（`src/router/index.js`）：Vue Router 路由配置，通过路由守卫进行权限控制。
- **Utils 层**（`src/utils/`）：request.js 封装 Axios 实例，添加请求拦截器（注入 Authorization 头）和响应拦截器（统一处理错误）。

**数据库**：MySQL 8.0，存储所有业务数据，所有表均包含 `deleted` 逻辑删除字段。

### 3.2 功能设计

本系统的功能模块划分为以下几个子系统：

**认证授权子系统**：处理用户注册、登录、密码修改、身份认证。采用 JWT Token 认证机制，登录成功后生成包含 userId、userType、memberId、coachId 的 Token，客户端在后续请求中通过 Authorization 头携带 Token。Spring Security 配置了 JwtAuthenticationFilter，对所有请求路径（除 `/auth/login` 和 `/auth/register` 外）进行 Token 验证。

**会员管理子系统**：管理会员的档案信息（姓名、性别、手机号、邮箱、健身水平、会员等级、积分、余额等）。支持新增、编辑、删除、冻结会员，可调整会员积分（记录调整原因），可将会员分配给指定教练。

**教练管理子系统**：管理教练的档案信息（姓名、特长、工作年限、资质证书、状态等）。教练可维护个人特长标签、上传资质证书。管理员可审核教练资质。

**课程管理子系统**：管理课程目录和分类。课程关联教练、上课时间、容量等信息。课程分类包括团课（瑜伽、普拉提、动感单车、力量训练等）和私教课。教练通过排班管理功能创建课程排班，排班数据自动进入会员可预约课程池。

**预约管理子系统**：处理课程预约的完整流程。会员预约课程时检查容量限制，预约成功后记录到 course_booking 表并累加课程的当前预约人数。预约状态包括"已预约"→"已签到"→"已完成"，会员可取消预约（未签到状态）。

**排班调度子系统**：管理教练的课程排班（日期、时间、课程、地点）。教练排班后，对应课程自动在会员"可预约课程"中展示。教练提交调班申请，管理员审批后自动更新排班时间，并通知所有已预约的会员。

**签到子系统**：支持会员每日签到，记录签到时间，自动计算连续签到天数，签到成功后增加积分。

**体测健康子系统**：记录和管理会员的体测数据，包括身高、体重、BMI、体脂率、肌肉量、基础代谢率、血压、心率等指标。教练可为所负责的会员录入体测数据，会员也可自行录入。

**积分商城子系统**：定义了积分任务规则（签到+10、完成课程+20、预约+5、评价+10等），记录所有积分变动流水。商品列表管理（实物/课程），会员使用积分兑换，兑换后扣除积分。

**绩效工资子系统**：记录教练的月度绩效评分（出勤、教学、服务、销售、学员反馈），记录工资明细（基本工资、课时费、绩效奖金）。教练可在个人端实时查看绩效评分和收入情况。

**消息通知子系统**：通过 member_message 表存储站内消息，消息类型包括系统通知、课程通知、教练通知、课程提醒。课程开始前定时任务（@Scheduled，每10分钟执行一次）自动推送提醒消息。教练调班、课程取消等事件触发自动通知。

**评价管理子系统**：会员对已完成的课程进行评分（1-5星）和文字评价。教练可查看评价内容并回复，回复后通知会员。

**器材管理子系统**：管理健身器材的库存信息（名称、类型、品牌、型号、状态、维保日期），上传器材图片。

**统计面板子系统**：为管理员提供系统运营数据的统计概览，包括会员总数、教练总数、课程数量、器材状态分布等。

### 3.4 社会健康、文化、法律相关设计

#### 3.4.1 健康相关设计

系统充分考虑了对会员健康数据的管理和保护。体测数据表（member_body_test）设计了丰富的健康指标字段，包括身高、体重、BMI、体脂率、肌肉量、基础代谢率、血压、心率等，这些数据仅对会员本人和其负责教练可见。系统通过健康评分字段（health_score，0-100分）对会员的当前健康状态进行量化评估，为教练制定个性化训练计划提供数据支撑。

#### 3.4.2 隐私保护设计

会员的手机号在教练端查询时进行了部分脱敏处理（显示为"138****1234"格式）。会员的密码采用 BCrypt 算法加密存储，即使数据库泄露也无法还原明文密码。所有用户操作通过 JWT Token 进行身份验证，Token 有效期设为 24 小时，超时后需要重新登录。

#### 3.4.3 积分激励机制

系统设计了积分激励规则，鼓励会员积极参与健身活动：每日签到奖励10积分，完成课程奖励20积分，预约课程奖励5积分，评价课程奖励10积分，完善个人资料一次性奖励50积分，邀请好友注册一次性奖励30积分。积分可用于兑换健身课程或实物商品，形成完整的激励闭环。

### 4.1 会员注册与认证模块

#### 4.1.1 后端实现

会员注册的接口定义在 `AuthController`，路径为 `POST /auth/register`。

```java
@PostMapping("/register")
public ApiResponse<String> register(@RequestBody UserInfo userInfo) {
    // 1. 检查用户名唯一性
    LambdaQueryWrapper<UserInfo> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(UserInfo::getUsername, userInfo.getUsername());
    if (userInfoMapper.selectOne(wrapper) != null) {
        return ApiResponse.error("用户名已存在");
    }
    // 2. BCrypt 加密密码
    userInfo.setPassword(passwordEncoder.encode(userInfo.getPassword()));
    userInfo.setStatus(1);
    // 3. 插入 user_info 表
    userInfoMapper.insert(userInfo);

    // 4. 如果是会员类型，自动创建 MemberInfo 档案
    if (userInfo.getUserType() != null && userInfo.getUserType() == 3) {
        MemberInfo member = new MemberInfo();
        member.setMemberName(userInfo.getUsername());
        member.setFitnessLevel("初级");
        member.setMemberLevel(1);
        member.setPoints(0);
        member.setBalance(0.0);
        member.setAccountStatus(0);
        member.setRegTime(LocalDateTime.now());
        memberInfoMapper.insert(member);
        // 回填 user_info.member_id
        userInfo.setMemberId(member.getMemberId());
        userInfoMapper.updateById(userInfo);
    }
    return ApiResponse.success("注册成功");
}
```

登录接口 `POST /auth/login` 使用 Spring Security 的 `AuthenticationManager` 进行用户名密码验证，验证成功后调用 `JwtUtil.generateToken()` 生成包含 userId、userType、memberId、coachId 的 JWT Token。

`JwtAuthenticationFilter` 拦截所有请求，从请求头中提取 Token，调用 `JwtUtil.validateToken()` 验证签名和有效期，将解析出的用户信息（userId、userType、memberId、coachId）以 `@RequestAttribute` 的方式注入到 Controller 方法参数中，供后续业务逻辑使用。

#### 4.1.2 前端实现

登录页面（`login/index.vue`）提供了登录和注册两个标签页的切换。登录表单包含用户名、密码和角色选择（管理员/教练/会员），注册表单包含用户名、密码、确认密码和角色选择（教练/会员）。登录成功后将 Token 存储到 Vuex 中，并根据角色跳转到对应首页：

```javascript
this.$store.dispatch('user/login', this.loginForm).then(() => {
  const ut = Number(this.loginForm.userType)
  let path = '/dashboard/index'
  if (ut === 2) path = '/coach-dashboard/index'
  else if (ut === 3) path = '/member/home'
  this.$router.push({ path })
})
```

所有 API 请求通过 `request.js`（封装 Axios 的实例）发送，请求拦截器自动在请求头中注入 `Authorization: Bearer ${token}`。

### 4.2 会员管理模块

#### 4.2.1 会员分配教练

会员表中通过 `coach_id` 字段关联负责教练。管理端的会员列表新增了「负责教练」列，已分配的显示教练姓名，未分配的显示"未分配"标签。「分配教练」按钮弹出教练选择框，选中教练后调用 `PUT /member/assign-coach` 接口更新会员的 `coach_id`：

```java
@PutMapping("/assign-coach")
public ApiResponse<String> assignCoach(@RequestBody MemberInfo memberInfo) {
    MemberInfo existing = memberInfoService.getById(memberInfo.getMemberId());
    if (existing == null) return ApiResponse.error("会员不存在");
    existing.setCoachId(memberInfo.getCoachId());
    memberInfoService.updateById(existing);
    return ApiResponse.success("教练分配成功");
}
```

分页查询会员列表时，`MemberInfoServiceImpl.getMemberPage()` 通过 join `coach_info` 表自动填充 `coachName` 字段，避免 N+1 查询问题：

```java
private void fillCoachNames(List<MemberInfo> members) {
    if (members == null || members.isEmpty()) return;
    List<Long> coachIds = members.stream()
        .map(MemberInfo::getCoachId)
        .filter(id -> id != null)
        .distinct()
        .collect(Collectors.toList());
    Map<Long, String> coachNameMap = new HashMap<>();
    coachIds.forEach(id -> {
        CoachInfo coach = coachInfoMapper.selectById(id);
        if (coach != null) coachNameMap.put(id, coach.getCoachName());
    });
    members.forEach(m -> {
        if (m.getCoachId() != null) m.setCoachName(coachNameMap.get(m.getCoachId()));
    });
}
```

#### 4.2.2 积分调整

管理员可调整会员积分，接口为 `PUT /member/points/{id}`，传入 `pointsChange`（正数为增加，负数为减少）和 `reason`（调整原因）。系统自动检查调整后积分不能为负数。

### 4.3 教练排班与预约联动模块

#### 4.3.1 排班数据联动

教练的排班通过 `CoachSchedule` 实体管理，包含教练ID、日期、时间、课程、容量等信息。教练在教练端创建排班后，系统自动将其暴露给会员端。

会员端调用 `GET /coach-schedule/available` 接口获取可预约课程：

```java
@GetMapping("/available")
public ApiResponse<List<CoachSchedule>> getAvailable(
        @RequestParam(required = false) LocalDate startDate,
        @RequestParam(required = false) LocalDate endDate) {
    LocalDate from = startDate != null ? startDate : LocalDate.now();
    LocalDate to = endDate != null ? endDate : LocalDate.now().plusDays(7);
    List<CoachSchedule> list = coachScheduleService.getScheduleList(from, to, null);
    return ApiResponse.success(list);
}
```

该接口默认查询当前日期起未来7天内的所有排班，返回给会员端以日历或列表形式展示，无需任何人工操作。

#### 4.3.2 调班自动通知

当教练提交调班申请（`POST /coach-shift`），管理员审批通过（`PUT /coach-shift`，status=1）时，系统自动执行以下操作：

（1）根据调班记录中的 `original_schedule_id` 找到原排班记录；
（2）将原排班的日期和时间更新为调班的目标日期和目标时间；
（3）通过 `coachId + courseId + 日期` 条件在 `course_booking` 表中查询所有已预约该课程的会员；
（4）遍历会员列表，调用 `memberMessageService.pushMessage()` 发送站内消息，通知课程时间已调整。

通知方法的核心实现如下：

```java
private void notifyAffectedMembers(CoachSchedule schedule, String content) {
    if (schedule == null || schedule.getCoachId() == null) return;
    LocalDateTime dayStart = schedule.getScheduleDate().atStartOfDay();
    LocalDateTime dayEnd = schedule.getScheduleDate().atTime(23, 59, 59);
    LambdaQueryWrapper<CourseBooking> wrapper = new LambdaQueryWrapper<>();
    wrapper.eq(CourseBooking::getCoachId, schedule.getCoachId())
           .eq(CourseBooking::getCourseId, schedule.getCourseId())
           .ge(CourseBooking::getClassTime, dayStart)
           .le(CourseBooking::getClassTime, dayEnd)
           .ne(CourseBooking::getStatus, "已取消");
    List<CourseBooking> bookings = courseBookingMapper.selectList(wrapper);
    String title = "课程[" + schedule.getCourseName() + "]调班通知";
    for (CourseBooking b : bookings) {
        memberMessageService.pushMessage(
            b.getMemberId(), "course", title, content,
            String.valueOf(schedule.getScheduleId()), "coach_schedule"
        );
    }
}
```

同样地，教练修改排班时间或删除排班时，也会触发 `notifyAffectedMembers()` 方法通知已预约的会员。

if (coachId != null) {

### 4.6 课程评价管理模块

#### 4.6.1 教练回复评价

会员对课程的评价存储在 `CourseReview` 表中，包含评分（rating，1-5）和评价内容（content）。教练可调用 `POST /course/review/reply/{id}` 接口回复评价：

```java
@PostMapping("/reply/{id}")
public ApiResponse<String> reply(@PathVariable Long id, @RequestParam String reply) {
    CourseReview review = courseReviewService.getById(id);
    boolean result = courseReviewService.reply(id, reply);
    if (result && review != null && review.getMemberId() != null) {
        memberMessageService.pushMessage(
            review.getMemberId(), "coach",
            "教练已回复您的评价",
            "教练回复：" + reply,
            String.valueOf(review.getReviewId()), "course_review"
        );
    }
    return ApiResponse.success("回复成功");
}
```

教练回复后，系统自动向对应的会员推送站内消息，通知其教练已回复。

#### 4.6.2 前端实现

教练端"我的评价"页面（`coach/myReviews.vue`）增加了回复功能：

- 已回复的评价显示"查看回复"按钮；
- 点击后弹出对话框，未回复时显示输入框，已回复时显示历史回复内容；
- 提交回复后刷新列表并提示"回复成功"。

### 4.7 积分商城模块

#### 4.7.1 积分任务规则

系统定义了6种积分任务类型（`PointsTaskType` 枚举），每种任务有独立的积分值和是否可重复执行的标志：

| 任务类型 | 任务名称 | 积分 | 是否可重复 |

| booking | 预约课程 | 5 | 是 |

### 4.8 课程预约与签到模块

### 4.9 定时任务模块

系统通过 Spring `@Scheduled` 注解实现定时任务，任务类为 `CourseReminderScheduler`。每10分钟执行一次，查询未来24小时内开始的课程预约记录，向未读提醒的会员推送课程开始提醒消息。

（1）**微信小程序支持**。目前系统仅支持 PC 浏览器访问，可基于现有后端 API 开发微信小程序，方便会员随时随地查看课程、预约签到。

（2）**智能推荐系统**。基于会员的体测数据、历史课程和积分偏好，开发课程智能推荐功能，提升会员健身体验和场馆课程利用率。

（3）**在线支付集成**。当前系统的会员消费采用线下支付记录的方式，可集成微信支付或支付宝，实现会员线上充值、购课、续卡的闭环。

（4）**数据可视化增强**。为管理员提供更丰富的数据分析图表（如会员增长趋势、课程热度排行、教练收入对比等），辅助经营决策。

（5）**Redis 缓存优化**。当前系统未启用 Redis 缓存，可通过 Redis 对热点数据（如课程列表、教练信息）进行缓存，减少数据库查询压力，提升系统响应速度。

（6）**教练训练计划管理**。当前系统已支持体测数据录入和课后作业布置，可在此基础上进一步开发教练制定周期性训练计划的功能，形成完整的训练计划-执行-反馈闭环。
